# 프로젝트 평가 항목 안내 — 경기 하루이음

[문서 안내](../README.md#문서-분류-기준)

## 평가 개요

프로젝트 평가는 기획 및 주제 적합성(20점), 핵심 기능 및 기술 구현도(35점), 데이터 및 AI 활용도(25점), 발표 준비도(20점)의 4개 영역을 합산해 총 100점으로 구성한다.

| 번호 | 평가 영역 | 배점 | 핵심 확인 내용 |
| --- | --- | --- | --- |
| 1 | 기획 및 주제 적합성 | 20점 | 프로젝트 주제·문제 정의, 서비스 목적·방향성, 조원별 역할 분담 기재 여부를 평가한다. |
| 2 | 핵심 기능 및 기술 구현도 | 35점 | 주요 기능 실제 동작(시연 동영상 기준), 기술 스펙·아키텍처 문서화, API·DB·서버 구현 안정성을 평가한다. |
| 3 | 데이터 및 AI 활용도 | 25점 | 외부 데이터 수집·OCR·RAG·LLM 등 데이터 기반 AI 활용과 발전 과정(history)의 시행착오·개선 내역을 평가한다. |
| 4 | 발표 준비도 | 20점 | 발표 PPT 전달력, 시연 동영상의 핵심 기능 표현, 발표 시간(10분) 준수 및 질의응답을 평가한다. |

## 영역별 세부 평가 기준과 관련 문서

각 세부 항목은 아래 기준을 따르며, 저장소 내 상세 내용은 원본 명세 문서를 참조한다.

### 1. 기획 및 주제 적합성 (20점)

| 번호 | 세부 평가 항목 | 관련 문서 및 현황 |
| --- | --- | --- |
| (1) | 프로젝트 주제와 해결하려는 문제가 명확한가 | [요구사항 범위](01-func/01-requirements.md#범위)에서 경기도 관광 탐색(시흥권 시연 데이터 기반)·AI 추천·패스 구성·방문 기록의 목표와 제외 범위를 정의한다. |
| (2) | 서비스의 목적과 방향성이 잘 드러나는가 | [핵심 기능 요구사항](01-func/01-requirements.md#핵심-기능-요구사항)과 [디자인 기준](02-uxui/01-design.md)에서 사용자 흐름과 화면 방향성을 정의한다. |
| (3) | 조원별 역할이 명확히 분담되어 기술문서에 기재되었는가 | 조원별 세부 역할 표는 미확정 상태이며, 팀 내 역할 확정 후 문서에 반영한다. |

### 2. 핵심 기능 및 기술 구현도 (35점)

| 번호 | 세부 평가 항목 | 관련 문서 및 현황 |
| --- | --- | --- |
| (1) | 주요 기능이 실제로 동작하는가 (시연 동영상 기준) | [사용 방법](../README.md#사용-방법)과 [최신 판정](04-test/01-verification.md#최신-판정)에서 5개 탭의 핵심 흐름과 검증 결과를 관리한다. |
| (2) | 기술 스펙과 아키텍처가 기술문서에 명확히 정리되었는가 | [기술 스택](../README.md#기술-스택)과 [기술 구조](03-tech/01-architecture.md)에서 헥사고날·클린 아키텍처 경계와 소스 구조를 정의한다. |
| (3) | API / DB / 서버 등 필요한 기술이 안정적으로 구현되었는가 | [HTTP API 계약](03-tech/01-architecture.md#http-api-계약), [데이터 저장과 동시성](03-tech/01-architecture.md#데이터-저장과-동시성), [배포 가이드](05-ops/01-deploy.md)에서 구현과 운영 구성을 다룬다. |

### 3. 데이터 및 AI 활용도 (25점)

| 번호 | 세부 평가 항목 | 관련 문서 및 현황 |
| --- | --- | --- |
| (1) | 외부 데이터 수집, OCR, RAG, LLM 등 데이터를 기반으로 AI 기능을 적절히 활용했는가 | [관광 데이터](../data/places.json), Open-Meteo 날씨 연동, CLOVA Studio·OCR·Voice·Papago 기반의 [도우미 확장](01-func/01-requirements.md#도우미-확장)을 구현했다. |
| (2) | 발전 과정(history)에 시행착오와 개선 내용이 드러나는가 | Git 커밋 이력, [최신 판정](04-test/01-verification.md#최신-판정), [남은 작업과 리스크](03-tech/01-architecture.md#남은-작업과-리스크)에서 검증·개선 내역과 제약 사항을 구분한다. |

### 4. 발표 준비도 (20점)

| 번호 | 세부 평가 항목 | 준비 기준 및 현황 |
| --- | --- | --- |
| (1) | 발표 PPT가 이해하기 쉽게 구성되어 있는가 | 기획 배경, 아키텍처, AI 활용, 시행착오와 개선 과정을 포함해 발표 자료를 제작한다. |
| (2) | 시연 동영상이 핵심 기능을 효과적으로 보여주는가 | 경기 둘러보기, 내 여행, 여행 도우미, 경기 날씨, 마이의 핵심 시나리오를 시연 동영상으로 녹화한다. |
| (3) | 발표 시간(10분)을 지키고 질의에 적절히 답변하는가 | 발표 시간을 10분 이내로 배분하고 기술 구조·보안 경계·남은 작업에 대한 질의응답을 준비한다. |

## 미확정 및 발표 준비 항목

| 항목 | 대기 이유 | 재개 조건·작업 |
| --- | --- | --- |
| 조원별 역할 기재 | 조원 명단과 담당 역할 정보를 아직 전달받지 못했다. | 조원별 담당 영역이 확정되면 기술 문서 또는 본 문서에 역할 분담표를 추가한다. |
| 발표 PPT 및 시연 동영상 | 최종 발표 일정과 제출 양식에 맞춰 별도 제작해야 한다. | 시연 시나리오와 NAVER 실키 연동 범위를 확정한 뒤 동영상 촬영과 PPT 구성을 진행한다. |
